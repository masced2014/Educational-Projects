## 🚀 Quick Start

```bash
# Build the tool
cargo build --release

# Encrypt a file (you'll be prompted for password twice for confirmation)
./target/release/secure-file-crypto encrypt -i myfile.txt -o myfile.txt.enc

# Decrypt a file (you'll be prompted for password)
./target/release/secure-file-crypto decrypt -i myfile.txt.enc -o myfile.txt
```

## 🔐 Security Features

- **AES-256-GCM Encryption**: Uses the Advanced Encryption Standard with 256-bit keys in Galois/Counter Mode
- **Authenticated Encryption**: Provides both confidentiality and authenticity of data
- **Integrity Protection**: Detects any tampering or corruption of encrypted files
- **Argon2 Key Derivation**: Derives encryption keys from passwords using Argon2, a memory-hard function resistant to GPU cracking attacks
- **Random Salt & Nonce**: Each encryption uses a unique random salt and nonce for maximum security
- **Memory Security**: Encryption keys are securely zeroed from memory after use where supported by the implementation
- **Cross-Platform**: Works on Linux, macOS, and Windows

## 📖 Usage

### Encrypt a File
```bash
# With password prompt (recommended for security)
# You'll be prompted to enter and confirm your password
secure-file-crypto encrypt -i secret.txt -o secret.txt.enc

# With password as argument (less secure, visible in shell history)
secure-file-crypto encrypt -i secret.txt -o secret.txt.enc -p "YourPassword123"
```

> **Note**: When using the interactive password prompt, you'll be asked to enter your password twice for confirmation. This helps prevent typos that could lock you out of your encrypted data.

### Decrypt a File
```bash
# With password prompt (recommended for security)
secure-file-crypto decrypt -i secret.txt.enc -o secret.txt

# With password as argument (less secure, visible in shell history)
secure-file-crypto decrypt -i secret.txt.enc -o secret.txt -p "YourPassword123"
```

### Help Commands
```bash
# General help
secure-file-crypto --help

# Encrypt command help
secure-file-crypto encrypt --help

# Decrypt command help
secure-file-crypto decrypt --help
```

## 🔬 Technical Details

### Encryption Process
1. **Key Derivation**: Your password is transformed into a 256-bit encryption key using Argon2id with a random 16-byte salt
2. **Nonce Generation**: A random 12-byte nonce is generated for this encryption operation
3. **AES-256-GCM Encryption**: The file is encrypted using AES-256 in GCM mode with the derived key and nonce
4. **File Format**: The output file contains `[SALT (16 bytes)][NONCE (12 bytes)][ENCRYPTED DATA][AUTH TAG (16 bytes)]`

### Decryption Process
1. **Extract Components**: The salt, nonce, and encrypted data (with auth tag) are extracted from the file
2. **Key Derivation**: The encryption key is re-derived from the password using the extracted salt
3. **Authenticated Decryption**: AES-256-GCM decrypts and verifies the integrity of the data in one operation
4. **Verification**: If the password is wrong or the file has been tampered with, decryption fails immediately

### Security Guarantees
- **Confidentiality**: Only someone with the correct password can read the file contents
- **Authenticity**: Any modification to the encrypted file will be detected during decryption
- **Integrity**: The authentication tag ensures data hasn't been corrupted or tampered with
- **Password Security**: Argon2id protects against brute-force and rainbow table attacks
- **Uniqueness**: Each encryption produces different output even for the same input (due to random salt/nonce)

## 📊 Performance

- **File Size Support**: Successfully handles files from single bytes up to 5MB+ (tested in robustness suite)
- **Memory Usage**: Reads the entire file into memory before encryption and decryption
- **Speed**: AES-256-GCM provides hardware-accelerated encryption on modern CPUs
- **Scalability**: Suitable for small and medium-sized files; very large files are limited by available system memory

Performance characteristics:
- Small files (< 1KB): Near-instant encryption/decryption
- Medium files (1-100MB): Typically completes in seconds
- Large files (> 100MB): Processing time scales linearly with file size

## 📦 Dependencies

This tool is built on trusted, industry-standard cryptographic libraries:

- **[aes-gcm](https://crates.io/crates/aes-gcm)** (v0.10): Pure Rust implementation of AES-256-GCM authenticated encryption
- **[argon2](https://crates.io/crates/argon2)** (v0.5): Winner of the Password Hashing Competition, used for key derivation
- **[zeroize](https://crates.io/crates/zeroize)** (v1.8): Securely zero sensitive data from memory
- **[clap](https://crates.io/crates/clap)** (v4.5): Command-line argument parsing
- **[rpassword](https://crates.io/crates/rpassword)** (v7.3): Secure password reading without echo

All cryptographic primitives are provided by the [RustCrypto](https://github.com/RustCrypto) project, which provides pure Rust implementations that are reviewed and maintained by the cryptography community.

## ❓ FAQ

### Is this tool secure enough for sensitive data?

Yes. This tool uses AES-256-GCM, which is approved by NIST and used by governments and enterprises worldwide. The implementation follows cryptographic best practices including random salts, unique nonces, and authenticated encryption. However, the overall security depends on:
- Using a strong password (16+ characters)
- Keeping your password secret
- Protecting encrypted files from unauthorized access

### Can I use this for production systems?

This tool uses battle-tested cryptographic libraries (RustCrypto) and follows security best practices. However, for mission-critical applications, you should:
- Perform your own security audit
- Ensure compliance with your organization's policies
- Consider additional security measures like key management systems
- Keep backups of important encrypted files

### What happens if I forget my password?

**There is no password recovery mechanism.** This is by design for security. Without the correct password, the encrypted data cannot be recovered. Always:
- Use a password manager to store passwords securely
- Keep secure backups of important passwords
- Test decryption before deleting original files

### Is the encryption quantum-resistant?

AES-256 is considered to have adequate security against quantum computers (requiring 2^128 quantum operations), though Argon2 key derivation could theoretically be weakened by quantum algorithms. For quantum-resistant encryption, consider post-quantum cryptographic algorithms, which are not currently implemented in this tool.

### Can encrypted files be shared across different operating systems?

Yes! The encrypted file format is platform-independent and works across Linux, macOS, and Windows. Just ensure both systems use the same version of this tool.

### Does this tool store my password anywhere?

No. Passwords are only held in memory during encryption/decryption operations and are securely zeroed afterward using the `zeroize` crate. They are never written to disk or logged.

## 🛡️ Security Best Practices

1. **Strong Passwords**: Use long, complex passwords (16+ characters with mixed case, numbers, and symbols)
2. **Password Managers**: Consider using a password manager to generate and store strong passwords
3. **Secure Storage**: Store encrypted files and passwords separately
4. **Password Prompt**: Use the interactive password prompt instead of command-line arguments to avoid password exposure in shell history
5. **Backup**: Keep encrypted backups in case of file corruption (but never store passwords with encrypted files)
6. **Regular Updates**: Keep the tool updated to benefit from security patches

```bash
secure-file-crypto encrypt -i secret.txt -o secret.txt.enc && shred -u secret.txt
```

## 🐛 Troubleshooting

### "Decryption failed: incorrect password or corrupted file"
- Verify you're using the correct password
- Check that the encrypted file hasn't been modified or corrupted
- Ensure you're using the same version of the tool that encrypted the file

### "Failed to read input file"
- Check that the file exists and you have read permissions
- Verify the file path is correct

### "Failed to create output file"
- Check that you have write permissions in the output directory
- Ensure the output directory exists
- Verify there's enough disk space
